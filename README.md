# marketo-sandbox

A local mock of the Marketo Engage REST API, generated from Marketo's official
Swagger documentation: each documented operation becomes a NestJS route that
answers with faker-generated data, so no Marketo tenant is needed.

## Project setup

```bash
$ npm install
```

## Compile and run the project

```bash
# development
$ npm run start

# watch mode
$ npm run start:dev

# production mode
$ npm run start:prod
```

The server listens on `127.0.0.1:3000` by default, so only this machine can
reach it. `HOST` and `PORT` change that (csh and tcsh set `HOST` on their own):

```bash
# another port
$ PORT=4311 npm run start

# reachable from other machines or containers
$ HOST=0.0.0.0 npm run start
```

## API documentation

When the application is running, Swagger UI is available at
[http://localhost:3000/api](http://localhost:3000/api). The generated OpenAPI
document is available at
[http://localhost:3000/api-json](http://localhost:3000/api-json).

## Mock Marketo API

This project mirrors five Marketo REST APIs and answers every request with
faker-generated data, so no Marketo tenant is required.

Like Marketo, it reads JSON and urlencoded request bodies up to 1 MB, so a
300-lead sync fits, and answers `413` above that. Multipart uploads are not
parsed.

All three generators read the documents in `docs/` and handle both Swagger 2.0
(`definitions`) and OpenAPI 3 (`components.schemas` / `requestBody` / `content`).
Each target owns one area under `src/`:

| Target           | Document                              | Area under `src/` | Schemas | Operations |
| ---------------- | ------------------------------------- | ----------------- | ------- | ---------- |
| `asset`          | `marketo-swagger-asset.json`          | `asset`           | 255     | 220        |
| `data-ingestion` | `marketo-swagger-data-ingestion.json` | `data-ingestion`  | 15      | 7          |
| `identity`       | `marketo-swagger-identity.json`       | `identity`        | 2       | 2          |
| `mapi`           | `marketo-swagger-mapi.json`           | `lead-database`   | 175     | 147        |
| `user`           | `marketo-swagger-user.json`           | `user-management` | 12      | 12         |

Each area is laid out identically — never edit these folders by hand, regenerate
them instead:

| Folder                          | Contents                          | Generator                                 |
| ------------------------------- | --------------------------------- | ----------------------------------------- |
| `src/<area>/<area>-definitions` | schemas, and `swagger-source.ts`  | `scripts/generate-marketo-definitions.py` |
| `src/<area>/resources`          | one Nest module per Swagger tag   | `scripts/generate-marketo-resources.py`   |
| `src/<area>/<area>-mocks`       | one faker factory per schema      | `scripts/generate-marketo-factories.py`   |
| `src/mocks`                     | shared seed and request-id helper | `scripts/generate-marketo-factories.py`   |

Only `src/<area>/<area>.module.ts` is hand-written; it wires the generated
resources module into `AppModule`. Every generated file opens with a two-line `// Code generated by … DO NOT EDIT.` header naming its generator, its Swagger document (the three shared files in `src/mocks` name only the generator) and the command that regenerates it. Each area's `swagger-source.ts` records its Swagger document and the sha256 of the committed bytes.

### Regenerating

```bash
# every generator, every target (needs python3 3.9+ and the Prettier of npm ci)
npm run generate:all

# fail if any generated file, or a Swagger document changed since, is out of date (npm run check, and so CI, runs this; generate:all fixes it)
npm run check:all

# one generator, some targets
npm run generate:definitions -- --target mapi user
npm run generate:resources -- --target identity

# a document that is not registered yet, written to src/billing/**
npm run generate:definitions -- --swagger docs/marketo-swagger-billing.json --area billing
```

To register a new document permanently, name it `docs/marketo-swagger-<name>.json` (so `.gitattributes` keeps its bytes) and add a `Target` to `TARGETS` in
`scripts/marketo_codegen.py`. All three generators pick it up automatically; then
add `src/<area>/<area>.module.ts` and import it from `AppModule`.

### Reproducible mock data

Responses are random by default. Set `MARKETO_MOCK_SEED` to pin them so the same
request returns the same payload across restarts:

```bash
MARKETO_MOCK_SEED=42 npm run start
```

Seeding also pins the reference date used by relative date helpers. Override it
with `MARKETO_MOCK_REF_DATE` (defaults to `2024-01-01T00:00:00.000Z`).
